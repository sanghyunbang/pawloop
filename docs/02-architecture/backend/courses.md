# Courses (내가 남긴 코스) — 백엔드 구현 메모

> 대상: `com.heattrip.heat_trip_backend.walk.course` 패키지. openapi `/api/courses`. 이슈 #339.
> 참조 계약: [openapi.yaml](../../04-api/openapi.yaml) `paths./api/courses`, `schemas.Course`
> 표: [schema.md §31](../../03-database/schema.md) · 마이그레이션 `27_course.sql`

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 리소스 책임 | 산책 기록 중에 "여기 좋다" 고 남긴 것. 이름·소개·태그와 **잘라 낸 선** |
| 왜 `walk` 모듈 안인가 | 코스는 `walk.path` 를 읽어 만든다. 별도 모듈로 빼면 `walk` 의 엔티티를 다른 모듈이 들여다보게 되고, 모듈 경계 위반이 하나 는다. 코스는 산책의 파생이라 같은 모듈에 둔다 |
| 저장 | `course` 표. FK 둘의 규칙이 다르다 — `users` CASCADE(탈퇴하면 그 사람의 글이 사라진다) · `walk` **SET NULL**(산책을 지워도 코스는 남는다) |
| 인가 | 다섯 경로 모두 인증. 공개 코스도 로그인한 사람에게만 준다 — 비인증으로 열면 그 목록이 곧 크롤링 대상이다 |
| rate limit | 쓰기 셋(`POST` · `PUT visibility` · `DELETE`)은 `walk-write` 버킷 |

## 2. 선은 서버가 자른다

```
walk.path ──▶ CoursePath.trimEnds ──▶ course.path
              양 끝 100m 를 버린다      (남은 길이 < 100m 이면 400)
```

앱이 자른 선을 받지 않는다. 받으면 "양 끝 100m 를 버린다" 는 약속을 **앱 버전마다** 다시 지켜야 하고, 안 자르는 옛 앱 하나가 그 사람의 집 앞을 공개한다. 그래서 요청에는 `walkId` 만 있고 선은 없다.

자르는 기준은 **점의 개수가 아니라 거리**다. 5m 마다 한 점이 찍힌 산책과 신호를 못 잡아 드문드문 찍힌 산책이 같은 규칙으로 잘려야 한다(`CoursePathTest`).

## 3. 남의 것과 없는 것은 같은 404

| 상황 | 응답 |
| --- | --- |
| 남의 **비공개** 코스를 부름 | `404` — 없는 코스와 같다. 갈라 주면 "그 번호는 있는데 남의 것" 이 새어 나간다 |
| 남의 **공개** 코스를 부름 | `200`, `mine: false` |
| 남의 산책으로 코스를 만들려 함 | `404` — `WalkRepository.findMineById` 가 소유권을 쿼리 안에서 본다 |
| 남의 코스를 지우거나 공개 범위를 바꾸려 함 | `404`, 그 코스는 그대로 |

## 4. "이웃 코스" 가 좌표를 안 받는 이유

`GET /api/courses/public` 에는 좌표 파라미터가 없다. 앱이 공개 목록 한 벌(최근 300개)을 받아 **기기에서** 가까운 것을 고른다 — 장소 카탈로그(#273)와 같은 방식이고, 위치를 서버에 보내지 않는 A안(#235)이다. 목록이라 `path` 는 시작점 하나뿐이고, 선은 상세에서 온다.

이 방식의 한계는 **공개 코스가 많아지면 한 벌이 커진다**는 것이다. 300개는 그 전까지의 임시 상한이고, 넘어가면 장소 카탈로그처럼 ETag + 파일 캐시로 옮기거나 격자 단위로 나눈다(산책 안전 지수 #336 이 격자를 쓰는 것과 같은 길).

## 5. 태그를 표로 나누지 않은 이유

`tags` 는 `leash,poopbag,shade` 를 콤마로 이은 문자열이다. 값이 **셋으로 닫혀** 있고 검색 조건으로 쓰지 않는다. 지금 표를 나누면 조인만 늘고, 늘어날 때 나누는 편이 싸다. 늘어나는 날의 신호는 "태그로 거르고 싶다" 는 요구다.
