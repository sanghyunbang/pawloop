# MVP 범위 (MVP Scope)

> **Pawloop(포루프)** MVP의 경계선 — 지금 만드는 것(In-scope)과 뒤로 미루는 것(Out-of-scope)을 명확히 구분하고, "무엇이 되면 MVP 완료인가"를 정의한다. 산책을 wedge로 좁게 시작한다.

관련 문서: [기능 명세](../01-design/feature-spec.md) · [로드맵](./roadmap.md) · [화면 목록](../01-design/screen-spec.md) · [ERD](../03-database/erd.md)

---

## 1. MVP 한 문장

> 로그인 없이도, **우리 아이 프로필 → 산책(GPS 트래킹·기록·통계) → 동반장소 지도 → 반려 커뮤니티** 네 축을 한 앱에서 매끄럽게 경험할 수 있다.

감정 여행(heattrip)에서 피벗하며 감정 요소는 전부 제거했다. MVP는 **"반려 일상 로그"의 첫 조각인 산책**에 집중하고, 나머지(건강·식사·병원 로그)는 post-MVP로 명확히 미룬다.

---

## 2. In-scope (MVP에 포함) vs Out-of-scope (MVP에서 제외)

| 축 | In-scope (MVP) | Out-of-scope (post-MVP / 확장) |
|:---|:---|:---|
| **① 산책** | 실시간 GPS 트래킹(경로 폴리라인·거리·시간·페이스 라이브 스탯) · 산책 기록 1건 저장 · 산책 기록 리스트 · 주간 통계(fl_chart 막대) · 자주 가는 곳 | 실측 GPS(현재 시뮬 이동) · 사진 첨부 · 날씨 자동 기록 · 산책 크루/동반 매칭 |
| **② 지도** | KTO 반려동반 실데이터(서울 45곳) · 병원/펫샵/산책로 레이어 · 카테고리 필터/범례 · 장소 상세 시트 · 북마크 | 병원/펫샵/산책로 **실데이터**(현재 더미) · 백엔드 프록시+캐싱 · 전국 확장 · 실시간 혼잡도 |
| **③ 커뮤니티** | 게시판 5종(산책로후기·동반장소·건강·병원·자유·자랑) · 글 목록/상세 · 반응 3종(도움돼요·귀여워요·공감) · 댓글 UI · 글 작성 | 백엔드 연동(현재 더미 데이터) · 이미지 업로드 · 신고/차단 · 알림 · 팔로우 |
| **④ 강아지 프로필** | 프로필(이름·견종·크기·나이·중성화·아바타) 조회·편집 · 홈 히어로 노출 | 다견(여러 마리) 관리 · 백엔드 동기화 · 접종/병원 이력 |
| **인증** | — (로그인 없이 로컬 상태로 전 기능 사용) | 소셜 로그인(카카오·구글 — 네이버는 보류, ADR-0010) · 회원 계정 · 서버 세션 |
| **위치** | 서울 고정 좌표 기준 지도/장소 | `geolocator` 실위치 · 위치 권한 플로우 · 현재 위치 기반 주변 검색 |
| **데이터/백엔드** | KTO 관광공사 API **직접 호출**(앱→data.go.kr) | Spring Boot 반려 API · MySQL 공간형 저장 · POI 캐시 · LOCALDATA/두루누비 파이프라인 |
| **확장 로그** | — | 건강 로그 · 식사 로그 · 병원/접종 기록 · 동네 로그 |

### 요약: 4대 In-scope

1. **산책** — 실시간 트래킹(시뮬) + 기록 + 주간 통계
2. **지도** — KTO 실연동 + 필터/범례/장소 시트 (병원·펫샵·산책로는 더미 레이어)
3. **커뮤니티** — 게시판·반응·댓글 UI (더미 데이터)
4. **강아지 프로필** — 조회·편집 + 홈 히어로

### 요약: 핵심 Out-of-scope (의도적으로 미룸)

- **로그인** — 소셜 로그인 UI/자산은 있으나 MVP 흐름은 로그인 없이 동작
- **실위치** — `geolocator` 의존성은 있으나 서울 고정, 실위치 미도입
- **실데이터** — 병원/펫샵/산책로는 더미, 백엔드 반려 API 미연동
- **확장 로그** — 건강·식사·병원·동네 로그 전부 post-MVP

## 4. MVP 완료 정의 (Definition of Done, DoD)

MVP가 "완료됐다"고 말하려면 아래를 **전부** 충족해야 한다.

### 4.1 기능 DoD (축별)

| 축 | 완료 기준 |
|:---|:---|
| **산책** | 산책 시작 → 트래킹 화면에서 경로 폴리라인과 라이브 스탯(거리·시간·페이스)이 갱신 → 종료 시 기록 1건이 리스트에 추가되고 통계 주간 차트에 반영된다. |
| **지도** | 지도 진입 시 KTO 서울 장소가 마커로 표시 → 카테고리 필터로 레이어 토글 → 마커 탭 시 장소 상세 시트(이름·주소·전화·이미지) 노출 → 북마크 토글 동작. |
| **커뮤니티** | 게시판 탭 전환 → 글 목록 → 글 상세(본문·댓글·반응) → 반응 3종 토글 · 새 글 작성 폼 제출까지 UI 흐름이 끊김 없이 동작(데이터는 로컬/더미 허용). |
| **프로필** | 홈 히어로에 현재 반려견이 표시되고, 편집 화면에서 이름·견종·크기·나이·중성화·아바타를 수정하면 즉시 반영된다. |

### 4.2 품질 DoD (공통)

- [ ] **5탭 네비게이션**(홈/지도/[산책 FAB]/커뮤니티/통계)이 모든 화면에서 안정적으로 전환된다.
- [ ] 앱 **첫 실행부터 로그인 없이** 4대 기능을 모두 사용할 수 있다(로그인 강제 게이트 없음).
- [ ] `flutter build`(Android, minSdk 23/compileSdk 36)가 **에러 없이** 성공한다. → [Android 빌드](./setup.md)
- [ ] 주요 화면에서 **크래시·프레임 드랍 없이** 스크롤/전환된다(디자인 시스템 글래스/블러 포함).
- [ ] KTO API 키(`--dart-define=YOUR_DECODING_SERVICE_KEY`)로 지도 장소가 **실제로 로드**된다(네트워크 실패 시 빈/에러 상태 처리). → [로컬 개발 환경](./setup.md)
- [ ] 더미/미연동 항목이 UI 또는 문서에서 **더미임이 드러나거나 자연스럽게 보인다**(가짜를 실데이터인 척하지 않음).
- [ ] 디자인 시스템(오라 배경·글래스 카드·Pretendard·Fluent Emoji)이 전 화면에 일관 적용된다. → [디자인 시스템](../01-design/design-system.md)

### 4.3 MVP DoD에 포함되지 않는 것 (명시적 제외)

아래는 충족하지 않아도 MVP 완료로 간주한다.

- 실측 GPS 트래킹 정확도 / 실위치 권한 플로우
- 병원·펫샵·산책로 실데이터 연동
- 백엔드(Spring Boot) 반려 API·MySQL 저장·서버 세션
- 소셜 로그인 실동작
- 이미지 업로드·알림·신고 등 커뮤니티 운영 기능
- 건강·식사·병원·동네 등 확장 로그

## 5. MVP → 확장 이행 순서 (요약)

MVP 완료 후 Out-of-scope를 어떤 순서로 붙일지의 밑그림. 상세는 [로드맵](./roadmap.md) 참고.

1. **실위치 도입** (`geolocator`) — 산책 실 GPS + 지도 주변 검색의 전제
2. **백엔드 연동** — 커뮤니티/산책 기록을 Spring Boot + MySQL(공간형)로 영속화
3. **실데이터 파이프라인** — LOCALDATA(병원) · 두루누비(산책로) 수집·좌표 변환(EPSG:5174→WGS84) · POI 캐시
4. **로그인** — 소셜 로그인 + 계정 기반 다기기 동기화
5. **확장 로그** — 건강 → 식사 → 병원/접종 → 동네 로그 순 확장

---

_이 문서는 MVP의 경계와 완료 기준을 고정하기 위한 SSOT다. 범위 변경 시 이 문서를 먼저 갱신한다._
