# 기능 명세 (Feature Spec)

> Pawloop(포루프)의 MVP 4대 기능(산책·지도·커뮤니티·프로필)과 신규 MVP 기능(가족 케어 & 채팅), 확장 기능의 목적·동작·데이터·상태를 정리한다. 실제 코드(`app/lib/v2`)를 기준으로 작성했으며, 더미/미연동 부분은 그대로 표기한다.

관련 문서: [ERD](../03-database/erd.md) · [화면 흐름](./user-flows.md) · [정보 구조(IA)](./information-architecture.md)

## 0. 요약

Pawloop은 "반려동물과 함께 걷고, 동네 반려인들과 연결되는 공간"을 지향한다. **산책을 wedge로** 좁게 시작해 지도(동반장소)·커뮤니티·프로필로 확장한다. 감정 여행(heattrip) 앱에서 피벗하며 감정 요소는 전부 제거됐다.

- 진입: `main.dart` → `MainShell`(`lib/v2/screens/main_shell.dart`)
- 네비 5탭 구성: **홈 · 지도 · 일정 · 커뮤니티 · 채팅** — 다섯 칸이 같은 폭이고 산책은 홈의 "산책 시작" 이 맡는다(#446). 일정은 #419 가 더했고 그때 커뮤니티·채팅의 번호가 하나씩 밀렸다. 통계는 탭이 아니라 `me_screen`·`today_screen` 둘에서 push 한다
- 상태관리: `ValueNotifier` + `ValueListenableBuilder` (경량). 탭 인덱스/지도뷰는 `RootTab`(전역 `ValueNotifier`)로 보관.
- 도메인 SSOT: `lib/v2/domain/pet.dart` (`DogProfile`, `PetCategory`, `PetPost` 등). 산책은 `lib/v2/data/walk_*.dart` 다(#145).

## 1. 산책 (Walk)

가장 핵심적인 wedge. "실시간 트래킹"과 "수기 기록", 두 경로로 산책을 남긴다.

### 1.1 실시간 산책 트래킹 — `walk_tracking_screen.dart`

| 항목 | 내용 |
|---|---|
| 목적 | 산책 중 경로·거리·시간·페이스를 실시간으로 보여주고, 종료 시 기록으로 저장 유도 |
| 진입 | 홈 "산책 시작" CTA |
| 동작 | 네이버 지도 위 라이브 스탯 패널(km·시간·페이스), 경로 폴리라인 + 헤드 마커, 카메라 추적. 일시정지/재개, 종료 |
| 종료 흐름 | 바텀시트(`WalkFinishSheet` — 시간·거리·페이스 요약 + **경로 미리보기**) → "기록 저장하기"(→ `CreateScreen(prefillPlace:'오늘 산책')`) / "저장 안 함" / **"경로 사진 저장"**(#310): 타일 없이 로컬 캔버스에 그린 PNG 를 기기 갤러리 앨범 Pawloop 에만 넣는다 — 네트워크 0, 업로드 경로 없음. A안 빌드(지도 키 없음)에서도 "내가 걸은 길" 이 보이는 자리다 |
| 데이터 | **실 GPS**: `LocationService.locate()` 로 첫 점을 잡고 `Geolocator.getPositionStream`(5m)을 구독. Haversine `_dist()`로 누적 거리. 위치를 못 쓰면 `WalkLocationDeniedScreen` 이 이유를 말하고 직접 입력으로 보낸다 — 가짜 경로를 그리지 않는다(#160) |
| 한 손 기록 | 스탯 패널 **위에 항상 보이는** 버튼 셋 — 배변·마킹·물(#340). 한 탭이 곧 기록이고 **5초 안에 같은 버튼을 다시 누르면 취소**다(확인을 묻지 않는다 — 확인이 붙으면 한 탭이 두 탭이 된다). 버튼은 56dp 이상. 아이콘은 시스템 이모지가 아니라 직접 그린다. 규칙은 `WalkMomentLog`(도메인)에 있고 화면은 그것을 부르기만 한다 — 이 화면은 지도·GPS 를 물고 있어 위젯 테스트로 못 띄운다 |
| 한 손 기록이 가는 곳 | 초안(`WalkDraft.moments`) · 스냅숏(#335) · 완료 시트와 저장 화면의 "배변 2회 · 물 1회" · 경로 그림의 점. 저장하면 `care-logs` 에 종류별로 한 줄씩(#326 과 같은 길). **어디서 눴는지는 안 나간다** — 좌표가 아니라 경로의 몇 번째 점인지로 들고, 그 경로는 A안(#235)에서 서버로 안 간다 |
| 상태 | `_seconds`, `_km`, `_paused`, `_path`(진행 경로), `_pathT`(점별 델타 초, `_path` 와 길이 동일), `_denial`(위치 판정 — `null` 이면 판정 전이라 지도를 만들지 않는다). `NaverMapController _ctrl` |
| 화면 꺼짐 | 포그라운드 서비스(안드로이드 알림 "…랑 산책 기록 중" · iOS `UIBackgroundModes/location`)로 화면을 꺼도 스트림이 이어진다. 5초마다 기기 저장소에 스냅숏(`WalkInProgressStore`)을 적고, 앱이 죽었다 살아나면 홈·산책 시작에서 "이어서 기록할까요?" 를 묻는다(#335). 실기기 측정은 이슈 댓글 |
| 남은 것 | 경로 자체는 `POST /api/walks` 로 `walk.path`(LINESTRING SRID 4326)에 저장된다 |

| 항목 | 내용 |

### 1.4 산책 안전 지수 — `walk_safety.dart` · `walk_safety_repository.dart` · `walk_safety_card.dart` (#336)

| 항목 | 내용 |
|:---|:---|
| 목적 | 홈에서 "지금 우리 아이랑 나가도 되나" 한 줄. 하드코딩 날씨 카드(#326)가 있던 자리 |
| 데이터 | 앱은 위경도를 5km 격자 번호(`kmaGrid`)로 바꿔 **우리 서버** `GET /api/walk-safety/now?nx=&ny=` 에 **인증 없이** 보낸다 — 위경도는 안 가고, 서버는 누구의 격자인지 모른다. 서버가 기상청 초단기실황(기온·습도·강수·PTY)과 에어코리아(격자 중심에서 가장 가까운 측정소의 PM10·PM2.5)를 부른다(키는 서버에만, #40). 위치가 없거나 서버가 503 이면 **카드가 없다** |
| 판정 | `WalkSafety.judge` — 순수 함수. 아래 표 |
| 화면 | 홈 카드: 아이콘 + 한 줄 + 근거("26°C · 미세먼지 보통(성수)"). 누르면 시트(7초 룰 · 시간대 · 보정 · "참고"). 산책 시작 직전 "피하세요" 면 한 번 묻는다("그래도 시작") — 막지 않는다 |
| 캐시 | 판정 30분(`WalkSafetyStore`). 아이를 바꾸면 같은 관측값으로 다시 판정 |

**판정 수치표 — 참고 기준(수의사 자문 전)**. 근거: AKC(아스팔트는 기온보다 최대 33°C 높다) · Blue Dog Pet Care/Four Paws(바닥 52°C 에서 60초면 화상, 기온 25°C 부터) · The Farmer's Dog/Animal Keeper(7초 룰, 오전 10시 전·오후 7시 후) · 환경부 PM2.5 등급(좋음 ≤15 · 보통 ≤35 · 나쁨 ≤75).

| 판정 | 조건 | 한 줄 |
|:---|:---|:---|
| 좋아요 | 위 어느 것도 아님(기온 < 25°C 또는 낮 시간 밖 · PM2.5 ≤ 35 · 비 없음) | "지금 나가기 좋아요" |
| 짧게 | 25~29°C 의 낮(10~19시) · 또는 PM2.5 36~75 · 또는 비 | "짧게 다녀오세요 · 바닥 7초 룰 확인" / "… 비가 와요" |
| 피하세요 | 30°C 이상의 낮 · 또는 PM2.5 > 75 | "지금은 피하고 저녁 7시 뒤에" / "지금은 피하세요 · 미세먼지가 나빠요" |
| 추워요 | -5°C 이하 · 소형견은 0°C 이하 | "옷 입히고 짧게 다녀오세요" |

보정: 단두종(품종 문자열에 퍼그·불독·시추·페키니즈·보스턴·복서·샤페이·그리펀·친) · 노령견(84개월 이상)은 더위 판정을 한 단계 보수적으로. 대형견은 28°C 낮부터 피하세요. 미세먼지 값이 없으면 기온으로만 판정하고 근거에 "미세먼지 정보 없음" 을 적는다.

### 1.5 산책 루틴 — 주간 목표 · 연속 일수 (#341)

| 항목 | 내용 |
|:---|:---|
| 목적 | 앱이 기록을 받기만 하고 **먼저 말을 걸지 않는다** — 페르소나 P3 의 "바빠서 건너뛰고 기억이 안 난다" 를 되돌려 주는 자리 |
| 어디 | 홈 요약 카드 안의 한 줄(`walk_goal_row.dart`). 아이가 없거나 **개가 아니면 줄 자체가 없다** — 산책 권장량은 개에 대한 자료라 고양이에게 제안하면 근거 없는 숫자가 된다 |
| 목표 | **주 단위**다(주 며칠 · 주 몇 분). 하루 목표는 못 지킨 날마다 실패를 만든다 — 화요일을 건너뛰고 토요일에 두 배로 걷는 것은 실패가 아니다. 기본 날 수는 **5일**이고 7 이 아니다 |
| 막대 | 날과 분 중 **덜 찬 쪽**으로 채운다(`WalkGoalProgress.ratio`) — 하루에 몰아 걸은 주가 "다 했다" 로 보이면 목표가 뜻을 잃는다 |
| 연속 일수 | 오늘까지 며칠 연속인가. **오늘 아직 안 걸었어도 어제까지의 연속은 살아 있다** — 저녁 7시에 "0일" 을 보여 주면 아직 나갈 수 있는 사람에게 끊겼다고 말하는 셈이다. 끊기면 그 자리를 **비운다**(0일이라고 쓰지 않는다) |
| 저장 | 기기에만(`WalkGoalStore`, `shared_preferences`). 아이마다 따로 — 소형견과 대형견의 권장량이 두 배 다르다. 서버에 둘 이유는 "가족이 같은 목표를 본다" 를 할 때 생긴다 |
| 데이터 | 이번 주 날 수·분은 `GET /api/walks/stats/weekly` 의 `weekKm`·`weekMinutes`(#341 이 더했다)에 **전송 대기 초안을 얹어** 센다. 연속 일수는 목록 첫 장에서 날짜만 모아 계산한다 — 서버에 질문을 하나 더 만들지 않는다 |
| 저녁 알림 | **푸시가 아니다**(`flutter_local_notifications`, #83 의 FCM 과 무관한 기기 안 예약). 그날 기록이 0 일 때만 사용자가 정한 시각(기본 **오후 7시**)에 **한 번**. 기록이 생기면 그날 것은 사라지고 내일로 간다. 지난 시각이면 지금 울리지 않고 내일이다 — 지난 시각의 알림은 잔소리다. **기본은 꺼짐**이고, 켜는 그 순간에만 권한을 묻는다(거절당하면 스위치를 되돌린다). 설정 → 알림 |
| 알림 문구 | "산책 다녀올까요? / {이름} 오늘 아직 산책 기록이 없어요". **날씨를 안 적는다** — 몇 시간 전에 예약되는 알림이라 아침에 잰 기온을 저녁에 보여 주면 틀린 숫자다. 안전 지수는 앱을 열면 그 자리에서 다시 잰다(§1.4) |
| 정확도 | **정확 알람(`SCHEDULE_EXACT_ALARM`)을 안 쓴다.** 그 권한은 사용자에게 한 번 더 묻는다. 실측(2026-09-07 에뮬레이터): 21:15:00 예약 → **21:19:14 도착, 4분 14초 늦음**. `dumpsys alarm` 의 `window=+4m13s` 와 같다 — 저녁 산책 알림에는 이 정도가 맞다고 봤다 |
| 알림을 누르면 | 그 알림이 말하는 자리로 한 번 간다(#486 후속) — 저녁 산책 알림은 **홈**("산책 시작" 이 거기), 일정 알림은 **일정 탭**, 주간 정리는 **통계 화면**. 앱이 꺼져 있었으면 떠서 홈이 그려진 뒤에 간다. 한 번만 간다 — 계속 끌고 가면 다른 탭에 머물 수 없다. payload 가 없는 옛 알림은 앱만 연다 |
| 주간 정리 알림 | **일요일 오후 7시** 한 번 — "이번 주 산책 정리가 준비됐어요 / 통계에서 이번 주 요약과 다음 주 제안을 볼 수 있어요"(#486 후속). 저녁 알림과 같은 기기 안 예약(`weekly_report_reminder.dart`, 정확 알람 안 씀)이고 설정에서 켠다(기본 꺼짐, 켤 때만 권한을 묻는다). **숫자 · 이름을 안 적는다** — 알림에 숫자를 넣으면 예약한 날의 숫자라서, 문장은 통계 화면이 그때 서버에서 읽는다. 시각을 따로 고르게 하지 않는다 — 주 1회 알림에 설정 한 줄을 더 쓸 값이 없다 |

**제안 표 — 참고 기준(수의사 자문 전).** 근거: [PDSA](https://www.pdsa.org.uk/pet-help-and-advice/looking-after-your-pet/puppies-dogs/how-much-exercise-does-your-dog-need) · [Dogster](https://www.dogster.com/dog-health-care/how-much-exercise-does-a-dog-need/) · Kennel Club 의 오래된 규칙. 화면도 이 말을 **"참고 · 크기와 나이로 제안한 값이에요 · 언제든 고칠 수 있어요"** 로 함께 적는다 — 우리는 그 아이의 건강 상태를 모른다.

| 대상 | 하루 권장 | 왜 |
|:---|:---|:---|
| 강아지(12개월 미만, 나이를 알 때) | **월령 × 5분**, 하루 두 번까지 | Kennel Club 규칙. 4개월이면 20분씩 두 번 |
| 성견 · 소형견 | **소형견 하루 30분** | 저에너지 소형견 20~30분의 위쪽 |
| 성견 · 중형견 | **중형견 하루 45분** | 일반 성견 30분~2시간의 아래쪽 |
| 성견 · 대형견 | **대형견 하루 60분** | 사역·스포팅 견종 60~120분의 아래쪽 |

**나이를 모르면(`ageMonths == 0`) 성견 기준이다.** 지금 앱의 등록 시트가 생일을 안 받아 대부분 0 이다. 강아지에게 성견 기준을 권하면 많고 성견에게 강아지 기준을 권하면 적은데, 모르는 상태에서는 **적게 권하는 쪽이 더 나쁘다** — 성견의 부족한 운동은 문제 행동으로 돌아온다.

## 2.5 동네 (#342)

| 항목 | 내용 |
|:---|:---|
| 왜 | 앱 이름값이 "동네" 인데 코드에 동네가 없었다. 커뮤니티는 전국 한 줄이고 게스트의 지도는 서울시청 기준이었다 |
| 무엇 | **사용자가 목록에서 직접 고른 행정동.** 단말이 잰 좌표가 아니라 사람이 고른 텍스트라 위치정보가 아니다 — 위치기반서비스 신고 전(A안 #235)에도 서버가 든다 |
| 고르기 | 설정 → 내 동네. 시도 → 시군구 → 동 세 단계 **와** 검색을 함께 준다. "현재 위치로 찾기" 는 **기기 안에서** 후보만 고른다(`RegionCatalog.nearest`) — 고르는 것은 사람이다 |
| 목록 | 전국 3,516개를 앱에 넣어 둔다(`assets/regions/hangjeongdong.json`, 285KB). 원자료는 통계청 SGIS, 가공본은 CC BY 4.0 이라 **출처 한 줄이 고르기 화면에 보인다** — 지우면 안 된다 |
| 서버로 | **코드 열 자리 하나**(`PUT /auth/me` 의 `neighborhoodCode`). 좌표도 이름도 안 보낸다 — 이름은 서버가 250줄 시군구 표에서 붙인다(받으면 아무나 자기 동네를 "청와대" 라고 적어 글 카드에 띄운다) |
| 커뮤니티 | 동네를 고른 사람에게만 `성동구` 칩이 보이고, 켜면 **같은 구**의 글만 온다(`?neighborhood=mine`). 구 코드를 쿼리로 받지 않는다 — 받으면 남의 동네 구경이 된다. 동네를 안 고른 사람의 글은 그 목록에 없다 |
| 글 카드 | 글쓴이의 동네를 **구까지만** 보여 준다(`Post.authorDistrict`). 동을 보이면 사는 곳이 그만큼 좁혀진다 |
| 지도 | 현위치를 못 받으면 서울시청 대신 **고른 동네**에서 연다. 안내도 "성수1가1동 기준이에요" 로 바뀐다 — 고른 사람에게 "서울시청 기준" 은 틀린 말이다 |
| 개인정보 | 처리방침 v1.6 의 수집 항목에 "동네(읍·면·동, 선택)" 와 "구까지만 보인다" 가 적혀 있다. 설정에서 지우면 서버에서도 지워지고, 탈퇴하면 계정과 함께 사라진다 |

| 데이터 모델 | `DogProfile{name, breed, size, ageMonths, neutered, avatarAsset}` + 파생 `ageLabel` |

> 목표: `dog` 테이블(user_id FK) 연동. 현재는 로그인/유저 개념 없이 단일 반려견 전역 상태.

## 6.5 일정표 (Schedule) — `schedule_screen.dart` (#419 · 서버 #418)

지금까지 앱은 **지나간 일만** 알았다. 케어 로그는 "누가 언제 했다" 이고(`occurred_at` 이 서버 시계라 미래를 못 넣는다), 산책은 끝난 산책이다. 앞으로 할 일을 적을 자리가 한 곳도 없어서, 가족은 병원 일정을 **채팅으로** 조율하고 그 결정은 스크롤 위로 사라졌다(§6.4 가 그 자리다).

| 자리 | 무엇 |
|:---|:---|
| 월 달력 | 날짜마다 **종류별 점**(넷 이상이면 `+`). **숫자를 안 적는다** — 한 칸이 좁아 무엇이 셋인지 알 수 없고, 색이면 병원인지 산책인지가 바로 보인다 |
| 그날 목록 | 시각 있는 것 먼저, 없는 것은 **"하루 종일"** 묶음. 한 줄은 `[아이콘] 제목 · 아이 · 담당 · 시각` + 완료 체크 |
| 필터 칩 | `전체`(기본) · 아이별 · `가족`. 아이 필터는 주인과 **겹쳐 쓸 수 있다** — "우리 가족 일정 중 보리 것" |
| `+` 시트 | 종류(산책·병원·투약·미용·목욕·사료·그 밖) → 제목 → 날짜/시각 → 아이 → 메모 |
| 빈 상태 둘 | 이 달에 아무것도 없으면 "아직 적어 둔 일정이 없어요 · 병원 예약부터 적어 볼까요". **이 날만 비었으면** "10월 15일은 비어 있어요" — 둘을 뭉치면 20일에 적어 둔 사람이 15일을 눌렀을 때 자기 것이 사라진 줄 안다 |
| 편집 충돌 | 서버가 **409 와 함께 최신 값**을 준다. 화면은 그것으로 바꾸고 "○○님이 방금 고쳤어요" 를 말한다 — 조용히 덮어쓰면 아빠가 옮긴 병원 시각이 엄마의 옛 화면으로 되돌아간다 |

**시각은 없어도 된다.** "이번 주말 목욕" 이 그렇다. **0시로 채우지 않는다** — 채우면 화면이 "00:00 목욕" 이라고 적게 되고, 그건 사용자가 안 정한 것을 정한 것처럼 보이게 한다.

**주인을 사용자에게 안 묻는다.** 계약에는 주인이 셋이지만(아이 · 가족 그룹 · 크루) 시트에 "이건 누구 것인가요" 를 물으면 사용자가 받는 것은 **가시성을 고르는 질문**이다. 가족 그룹이 있으면 `group`, 없으면 `dog` 이고, 시트가 결과를 한 줄로 말한다 — "우리 가족이 함께 봅니다" / "이 일정은 나만 봅니다". 크루(`room`)는 값만 열려 있고 서버가 아직 400 으로 거절한다(#417).

**아직 없는 것**: 크루(`room`) 주인 — 값만 열려 있고 서버가 400 으로 막는다(#417). 고치기 시트 · 담당자 · 케어 연결 · 알림 · 반복은 전부 실렸다(#420·#421).
