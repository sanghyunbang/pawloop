# 출시 기록

어느 빌드가 어느 스토어에 언제 나갔는지. **README 가 아니라 여기에 적습니다** — README 는 "이
저장소가 무엇인가" 를 적는 곳이라 출시마다 고치면 금방 낡습니다.

## 버전 규칙

`pubspec.yaml` 의 `version: 2.0.0+1` 에서 앞이 **표시 버전**, 뒤가 **빌드 번호**입니다.

* **앞 숫자(`2.0.0`)는 두 스토어에서 같아야 합니다.** 사용자가 보는 번호입니다.
* **뒤 번호는 스토어마다 달라도 됩니다.** 애플과 원스토어는 서로의 번호를 모르고, 각자 "그
  스토어에 올린 이전 것보다 크기만" 하면 받습니다.
* 그래도 **되도록 맞춥니다.** 어긋나면 사람이 헷갈립니다 — 2026-09-18 에 실제로 그랬습니다
  (iOS 는 `3`, 원스토어는 `1` 이었습니다).

빌드할 때 `--build-number` 로 덮어씁니다. `pubspec.yaml` 은 안 고칩니다 — 고치면 커밋이
생기고, 어느 커밋이 어느 빌드인지가 오히려 흐려집니다.

```bash
# iOS (App Store)
flutter build ipa --release --build-number=N --dart-define-from-file=dart-define.json

# Android (원스토어)
flutter build apk --release --build-number=N --dart-define-from-file=dart-define.json
```

`--dart-define-from-file` 을 빼면 **앱이 `http://10.0.2.2:8080` 을 보게 되어 통째로 죽습니다.**
지도 키도 빠져 지도 자리에 안내 카드만 뜹니다.

## 스토어별로 다르게 적는 것

같은 사실을 두 스토어가 다른 칸에 묻습니다. **답이 어긋나면 안 됩니다.**

| | App Store | 원스토어 |
|:---|:---|:---|
| 개인정보 수집 | `앱이 수집하는 개인정보` — 이름·이메일·사용자 ID·사용자 콘텐츠·피트니스 | `정보수집 및 공유 여부` → **예** |
| 위치 | **`대략적인 위치`** · 신원에 연결됨 · 앱 기능 | `위치 정보` → **예** → `대략적인`·`정확한` 둘 다 → 서버 **`미전송`** |

### 왜 애플엔 "대략적", 원스토어엔 "정확한" 인가

**질문이 다릅니다.** 애플의 `collect` 는 **기기 밖으로 내보내는 것**만 뜻합니다. 정확한 좌표는
안 나가니 애플 기준으로는 수집이 아니고, 나가는 것은 사용자가 고른 행정동뿐이라 `대략적인 위치` 입니다.

원스토어는 두 칸으로 쪼개 묻습니다 — `무엇을 수집하나`(기기 안까지) 와 `서버로 전송하나`. 그래서
기기가 읽는 것을 그대로 적고(`대략적인`·`정확한` 둘 다 — 안드로이드는 사용자가 "대략적으로만"
허용할 수 있고 매니페스트에 `ACCESS_COARSE_LOCATION` 이 있습니다) 전송은 `미전송` 입니다.

**어긋나 보이지만 같은 말입니다 — 정확한 좌표는 서버에 안 나간다.** `LocationUploadPolicy` 가 관문이고
(`UPLOAD_LOCATION` 기본 꺼짐), 날씨 격자마저 **단말이 잰 좌표가 아니라 고른 행정동의 중심**에서
계산합니다(`walk_safety_card.dart:105`, #682).

**경로를 서버에 저장하기로 하면 양쪽 다 고쳐야 합니다** — 애플은 `정확한 위치`, 원스토어는
`전송` 으로. 그 전에 위치기반서비스사업 신고가 먼저입니다([#412](https://github.com/sanghyunbang/pawloop/issues/412)).

항목마다 **수집 목적**을 또 묻습니다. 전부 `앱 기능` 하나만 골랐습니다 — 분석·광고·개인화 SDK 가 없습니다.

| 칸 | 답 | 근거 |
|:---|:---|:---|
| 개인정보 | **예** — 이름·이메일 주소·사용자 ID | 소셜 로그인이 주는 셋. 주소·전화번호·민감정보는 안 받음 |
| 개인정보 취급방침 | `https://pawloop.app/privacy` | `backend/Caddyfile:106` 이 `/privacy` 로 띄웁니다 |
| 위치정보 | **예** — 대략적·정확한 → **미전송** | 위 절 |
| 금융정보 | 아니오 | 결제·인앱구매 0 |
| 건강 및 피트니스 | **예** — `피트니스 정보` | 산책 거리·시간이 서버에 올라갑니다. `건강 정보`(의료)는 아님 |
| 사진 및 동영상 | **예** — 사진·동영상 | 커뮤니티 글에 둘 다 붙습니다(`post_media_field.dart:344` 가 영상 버튼) |
| 오디오 · 파일 및 문서 | 아니오 | 안 받음 |
| 메시지 | **예** — `기타 인앱 메시지` | 채팅 본문이 서버에 저장됩니다 |
| 앱 활동 | **예** — `기타 기록` | 툴팁이 "메모, 댓글, 리뷰, 좋아요" — 커뮤니티 글·댓글·반응이 여기. `앱 상호작용`·`앱 검색 기록`은 안 쌓습니다 |

| 기기 또는 기타 ID | 아니오 | 광고 ID 없고 `RefreshToken.java:47` 이 "device_id 컬럼은 두지 않았다" |

### APK 를 올릴 때

`Android 상품관리 > 신규 바이너리` 에서 **`앱 서명 사용 안함`** 을 고릅니다. 우리 APK 는 이미
`~/keystores/pawloop-upload.jks` 로 서명돼 있고, **`앱 서명 사용` 으로 바꾸면 서명이 달라져 기존
사용자가 업데이트를 못 받습니다.** 지난번에 뭘 썼는지는 화면 어디에도 안 적혀 있는데, `앱 서명 사용` 을
누르면 키를 **새로 올리라고 묻는 것**으로 압니다 — 등록된 키가 없다는 뜻이니 지난번은 `사용 안함` 입니다.
